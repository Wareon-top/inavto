# Этап 1 — сравнение, галерея и дожим

## Точка отката

- GitHub-ветка: `checkpoint/stage-0-security`
- локальный тег разработки: `checkpoint-stage-0-security`
- рабочая ветка Этапа 1: `agent/stage-1-conversion`

Checkpoint указывает на проверенное состояние после Этапа 0. Он создан до
первого изменения Этапа 1. Данные SQLite, каталог и загруженные фотографии в
Git не входят и откатом кода не удаляются.

## Что входит в этап

1. Сравнение до трёх моделей с сохранением выбора в браузере и мобильной
   таблицей.
2. Полноэкранный просмотр галереи: стрелки, клавиатура, счётчик и миниатюры.
3. Desktop exit-intent один раз за вкладку с честным предложением расчёта.
4. «Горящие лоты», которые включаются менеджером только при наличии прежней
   цены и будущего срока. Просроченные лоты автоматически скрываются.
5. Клиентский трекер по адресу `/status/<секретный-код>` поверх существующего
   защищённого API личного кабинета.

## Защита 85 автомобилей

Миграция добавляет в `site_cars` только два пустых столбца:
`hot_old_price` и `hot_deadline`. Она не обновляет и не удаляет строки. Перед
выкладкой `deploy/update.sh` по-прежнему создаёт SQLite backup и сверяет число
автомобилей до и после перезапуска.

Отдельная миграционная проверка выполнена на базе с 85 строками: после
добавления столбцов осталось 85 строк.

## Проверка после выкладки

- каталог показывает прежние 85 автомобилей;
- можно выбрать 2–3 автомобиля и открыть сравнение;
- главное фото карточки открывается на весь экран, стрелки и Escape работают;
- без настроенных лотов блок «Горящие лоты» скрыт;
- после настройки реального лота в админке видны старая цена и таймер;
- созданная в журнале сделки клиентская ссылка имеет вид `/status/<код>`;
- неверный или короткий код трекера возвращает 404.

## Откат кода

На сервере сначала убедиться, что рабочее дерево чистое: `git status --short`.
Затем получить checkpoint и переключиться на него отдельной веткой:

```bash
cd /opt/inavto
git fetch origin checkpoint/stage-0-security
git switch -C rollback/stage-0-security --track origin/checkpoint/stage-0-security
sudo bash deploy/update.sh
```

Добавленные пустые столбцы SQLite можно оставить: Этап 0 их игнорирует. Не
нужно удалять столбцы или восстанавливать базу, если количество и содержимое
машин не изменялись.
