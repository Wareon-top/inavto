# Этап 0 — безопасное обновление

Изменения этого этапа не меняют схему или содержимое таблицы `site_cars` и
не запускают импорт каталога.

## Перед публикацией

1. Убедиться, что `/etc/inavto.env` содержит действующие `ADMIN_TOKEN` и
   `STAFF_TOKEN` (если используется доступ представителя).
2. Если сайт и API размещены на разных origins, перечислить их через запятую
   в `CORS_ORIGINS`. Для одного домена переменную можно оставить пустой.
3. Запустить обычное обновление:

   ```bash
   sudo bash /opt/inavto/deploy/update.sh
   ```

Скрипт до `git pull` создаёт согласованный SQLite snapshot в
`/var/lib/inavto/backups/`, считает автомобили в `site_cars`, а после запуска
проверяет количество повторно. При расхождении он останавливается с
предупреждением и показывает путь к backup. Автовосстановления нет: оно
выполняется только вручную после проверки причины.

## Проверка после обновления

- `/api/health` отвечает `200`;
- `/api/orders` без Bearer-токена отвечает `401`;
- каталог на сайте показывает прежнее количество машин;
- админка открывает каталог, CRM, сделки и защищённые документы;
- ссылка личного кабинета открывает только документы этого клиента.

Старые прямые URL вида `/uploads/docs/...` после обновления возвращают `404`.
Документы не удалены: админка и личный кабинет скачивают те же файлы через
защищённые API-маршруты.
