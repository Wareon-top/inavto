# ТЗ: глобальное улучшение сайта INAVTO ASIA

**Версия:** 1.0 · **Дата:** 05.07.2026
**Объект:** сайт `site/` (12 страниц + 24 SEO-страницы моделей, монохромный editorial-дизайн, backend Express + Telegram-бот)
**Цель документа:** зафиксировать полный объём работ по двум направлениям — «Дизайн» и «Бизнес-воронка» — с приоритетами, критериями приёмки и списком того, что должен предоставить заказчик. Реализация — отдельными этапами после согласования.

---

## 1. Цели и KPI

| Метрика | Сейчас (оценка) | Цель после внедрения |
|---|---|---|
| Конверсия посетитель → лид | ~1–2% (типовая для ниши) | 4–5% |
| Доля лидов с квиза + калькулятора | — | ≥ 50% |
| Глубина просмотра (стр./визит) | ~1,5 | ≥ 2,5 |
| LCP mobile | ~1,5 с (лёгкий статик) | удержать < 2,0 с после добавления фото |
| Возврат к брошенной заявке | 0% (не ловим) | ≥ 10% возвращённых |

Главный принцип: каждый элемент ниже привязан к шагу воронки, а не к «красоте ради красоты».

---

## 2. Аудит текущего состояния

**Сильное (не трогаем, развиваем):**
- Монохромная editorial-система (Unbounded + Inter, 1px линии, контурная типографика) — узнаваемая, не шаблонная.
- SEO-фундамент: статические страницы моделей с Schema.org, sitemap, ЧПУ.
- Механики захвата: квиз, калькулятор, липкая мобильная CTA-панель, цели Метрики в коде.
- Единая платформа с Telegram Mini App (общий API заявок).

**Слабое (предмет этого ТЗ):**
1. **Фото.** Есть только 1 фото (hero). Каталог на силуэтах — главный тормоз доверия и конверсии.
2. **Воронка обрывается после «Спасибо».** Нет прогрева: заявка ушла — контакт с сайтом закончился. Брошенный квиз/калькулятор теряется навсегда.
3. **Нет соцдоказательств.** Ни вручений, ни отзывов, ни цифр «сколько привезли» — при чеке 3–6 млн ₽ это ключевое возражение.
4. **Квиз общий для всех.** Перекуп и частник проходят один сценарий; «холодный» трафик не сегментируется.
5. **Карточка модели тонкая.** Одна картинка, нет комплектаций/цветов, нет «цена у дилера vs у нас», нет похожих сценариев выбора.
6. **Нет дефицита/динамики.** Статичный каталог не создаёт повода вернуться (нет «горящих лотов», изменений цен).
7. Контакты-заглушки, домен не задан, Метрика не вставлена (блокирует запуск рекламы).

## 3. Направление «Дизайн»

### 3.1. Фотосистема (P0 — фундамент всего остального)

- **Стандарт фото модели:** PNG/WebP с вырезанным фоном (как hero), вид сбоку ¾, разрешение ≥ 1280px по ширине. Один ракурс = единый строй каталога.
- **Карточка каталога:** фото на светлой подложке #F0F0F0 с 1px рамкой; при ховере — фото «выезжает» на 4% + бликовая полоса (эффект уже реализован для SVG, переключить на `<img>`).
- **Страница модели:** галерея 3–6 фото (экстерьер, салон, багажник, экран) с миниатюрами-табами в чертёжной рамке; зум по клику (лайтбокс без сторонних библиотек).
- **Fallback-цепочка:** фото → чертёжный line-art (уже есть) — сайт никогда не показывает «битую» картинку.
- Пайплайн: скрипт `build-images.mjs` — автоконвертация загруженных PNG в WebP (реализация по образцу hero, 44 КБ/фото), генерация миниатюр.

### 3.2. Главная страница

- **Hero:** к текущей композиции (текст → авто снизу) добавить: тонкую линию-«пол» под машиной с подписью модели и ценой «от…» (кликабельно → страница модели); ротацию 3–4 hero-автомобилей (случайный выбор при загрузке — эффект «живого» сайта).
- **Блок «Выданные авто»** (новый, после трекера): горизонтальная лента фото вручений в чертёжных рамках с подписями «Модель · город · срок доставки фактический». Это витрина доверия №1.
- **Блок «Цифры»:** счётчики в стиле инженерной таблицы (авто доставлено / городов / средний срок / лет на рынке) с анимацией набора при появлении.
- **Мини-калькулятор в hero-зоне** (упрощённый: бюджет → страна → «Посчитать») — ведёт на полный калькулятор с предзаполненными полями.

### 3.3. Каталог и карточка модели

- **Карточка каталога:** добавить бейджи-статусы: «Хит», «Горящий лот −N%», «Под льготный утильсбор (до 160 л.с.)» — 1px рамки, uppercase, без цвета (чёрный/белый инверсией).
- **Сравнение моделей:** чекбокс «Сравнить» на карточках → липкая панель снизу → таблица сравнения до 3 моделей (инженерная таблица 1px — идеально ложится в дизайн-систему).
- **Страница модели:** блок комплектаций (таблица: название / отличия / цена под ключ); блок «Цена у дилера РФ vs INAVTO» с выгодой; блок «Как формируется цена» (мини-смета из калькулятора для этой модели).
- **«Похожие» → «С этой моделью сравнивают»** + кнопка сравнения.

### 3.4. Микровзаимодействия и полировка

- Заголовки: появление построчно (маска + translateY) вместо общего fade — дороже выглядит, дёшево делается.
- Числа в статистике и калькуляторе — анимация набора (count-up), `tabular-nums` уже есть.
- Прогресс-бар чтения на длинных страницах (тонкая чёрная линия под шапкой).
- Состояния форм: инлайн-валидация с подсказкой под полем (не только красная рамка); кнопка отправки со спиннером-точкой.
- Тёмная тема НЕ вводится (осознанное решение: монохром на бумаге — часть бренда).

### 3.5. Мобильный UX

- Квиз: полноэкранный на мобильном (не попап) — выше доходимость до конца.
- Каталог: горизонтальный скролл фильтров-пилюль вместо выпадающих списков на первом экране + кнопка «Все фильтры».
- Липкая CTA-панель: скрывать при открытой клавиатуре и внутри форм (не перекрывать поля).

## 4. Направление «Бизнес-воронка»

Карта воронки: **Захват → Квалификация → Прогрев → Сделка → Удержание/Рефералы.** Сейчас реализован только «Захват». Достраиваем остальное.

### 4.1. Захват (усиление)

1. **Сегментация квиза на входе** (первый вопрос): «Для себя / Для перепродажи». Ветка перекупа — короткая (объём, регион, контакт), ведёт на условия для бизнеса; ветка частника — текущая. Разные тексты «Спасибо».
2. **Лид-магнит из калькулятора:** после расчёта — кнопка «Получить смету PDF + чек-лист „Как не потерять деньги при заказе авто из Азии“» в обмен на телефон/Telegram. Генерация PDF — на backend (или отправка ботом сообщением со сметой).
3. **Сохранение брошенных форм:** localStorage-черновик квиза/калькулятора; при возврате — «Продолжить с шага 3?». Если введён телефон, но нет отправки — событие в Метрику `form_abandon` (ретаргетинг-аудитория).
4. **Exit-intent попап (только desktop, 1 раз за сессию):** «Уходите без расчёта? Пришлём подборку в Telegram» — одна кнопка перехода в бот с deep-link (utm в start-параметре).
5. **«Горящие лоты»** (новый тип данных в `data.js`: `hot: {oldPrice, deadline}`): блок на главной + бейджи в каталоге + таймер до конца резерва. Повод вернуться и триггер срочности. Правило честности: только реальные лоты.
6. **Подписка на снижение цены** на странице модели: «Следить за ценой» → Telegram-бот.

### 4.2. Квалификация и обработка (backend/CRM)

1. **Скоринг лида в боте:** заявка приходит менеджеру с тегами (сегмент, бюджет, источник utm, страница). Формат сообщения бота расширить: `#перекуп #бюджет4-6 #utm_direct #страница:zeekr-001`.
2. **SLA и статусы:** статусы лида (новый → взят → расчёт отправлен → думает → сделка/отказ+причина) — в существующей SQLite + команды боту. Отчёт «необработанные > 1 часа» — автопинг в чат менеджеров.
3. **Коллтрекинг:** подменный номер (Calltouch/CoMagic или простая схема «2 номера: сайт/остальное») — без него не посчитать рекламу, т.к. половина ниши звонит.

### 4.3. Прогрев (новое)

1. **Цепочка в Telegram-боте после заявки** (3–5 касаний, интервалы 0/1/3/7 дней): расчёт → вручение недели (фото) → «как проходит проверка перед выкупом» (видео) → шаблон договора → персональное предложение. Механика уже наполовину есть: бот и БД существуют.
2. **Ретаргетинг-пиксели:** VK Ads + Яндекс.Аудитории на всех страницах; аудитории: «был в каталоге», «считал калькулятор», «бросил квиз».
3. **Блок «Телеграм-канал»** на сайте (после первого экрана каталога): «Живые лоты и вручения — раньше, чем на сайте» — канал как прогревочный актив.

### 4.4. Сделка и после (удержание → рефералы)

1. **ЛК-трекинг** (фаза 2, есть в стратегии): страница `/status/<код заказа>` без логина — статус, фото, документы. Ссылку клиент получает в боте. Это же — главный источник рефералов («смотри, как едет моя машина»).
2. **Рефералная программа:** «Приведи друга — 30 000 ₽ после его вручения» — блок в ЛК и в финальном сообщении цепочки.
3. **Контент-цикл вручения:** чек-лист менеджеру: фото вручения → карточка в «Выданные авто» → пост в TG-канал → просьба об отзыве на Яндекс.Картах. Каждая сделка кормит воронку следующей.

### 4.5. Аналитика воронки (сквозная)

- Воронка в Метрике: просмотр каталога → карточка модели → открытие квиза/калькулятора → шаг N → лид (события уже частично прошиты: `quiz_open`, `lead_submit`; добавить `quiz_step_N`, `calc_used`, `compare_used`, `hot_view`).
- UTM прокидывать в payload заявки (поле `source`) — сквозная связка «канал → сделка» в SQLite.
- Еженедельный автоотчёт ботом: лиды по источникам, конверсия по шагам, необработанные.

## 5. Технические требования

- Скорость: суммарный вес главной ≤ 700 КБ с фото (WebP, lazy, `fetchpriority` на hero); LCP mobile < 2,0 с.
- Доступность: контраст выдержан (монохром — ок), фокус-состояния на всех интерактивных элементах, `prefers-reduced-motion` соблюдается (уже да — сохранить при новых анимациях).
- Все новые блоки — в текущей дизайн-системе (`style.css`, 1px, radius 0, Unbounded/Inter), без сторонних UI-библиотек.
- Новые данные (комплектации, горящие лоты, вручения) — расширение `data.js` + генератор `build-pages.mjs`; админ-редактирование — фаза 2.
- A/B (фаза 2, при трафике > 100 визитов/день): заголовок hero, текст CTA квиза, наличие exit-intent.

## 7. Этапы и приёмка

**Этап A (1-я итерация): фото-каталог + сегментация квиза + брошенные формы + «Выданные авто» + пиксели.**
Приёмка: каталог ≥ 10 моделей с фото; квиз ветвится; черновик формы восстанавливается после перезагрузки; блок вручений на главной; аудитории собираются.

**Этап B: горящие лоты + сравнение + расширенная карточка модели + скоринг в боте + SLA-статусы.**
Приёмка: лот с таймером на главной; сравнение 3 моделей работает на мобильном; заявка приходит с тегами; статусы переключаются командами бота.

**Этап C: цепочка прогрева в боте + лид-магнит PDF + ЛК-трекинг + рефералка + автоотчёты.**
Приёмка: тестовый лид получает цепочку по расписанию; смета уходит файлом; страница статуса открывается по коду; недельный отчёт приходит в чат.

Каждый этап: реализация → проверка в браузере (desktop+mobile) → обновление живого превью → согласование → пуш.
