# Админка каталога INAVTO ASIA

Адрес после установки на сервер: `http://<IP-сервера>/admin` (с доменом — `https://домен/admin`). Страница закрыта ключом.

**Установка на VPS (Sprintbox)** — пошагово для владельца: `docs/DEPLOY-SPRINTBOX.md`. Скрипты: `deploy/install.sh` (первичная установка) и `deploy/update.sh` (обновление).

## Что умеет
- Добавлять/редактировать/скрывать/удалять автомобили каталога сайта.
- Описание, характеристики, теги-фильтры, порядок вывода.
- Цены в трёх валютах: ₽ (под ключ, в млн — показывается на карточках), ¥ (цена в Китае), $ (опционально) — обе показываются на странице модели.
- Фото: перетащите файлы — они сжимаются в браузере до 1280px WebP и загружаются на сервер. Первое фото — главное (показывается на карточке вместо силуэта).
- Кнопка «Импортировать 16 моделей сайта» — первичное наполнение из встроенного каталога.
- **Импорт из CSV**: кнопка «Шаблон CSV» отдаёт таблицу-образец (открывается в Excel), заполняете и загружаете через «Импорт из CSV». Понимает UTF-8 и кодировку русского Excel, разделители `;` и `,`. Машины с совпадающим слагом обновляются — удобно массово менять цены. Колонка `cond` — new/used, `mileage` — пробег в км.

## Массовая загрузка фотографий по ссылкам (из админки — без сервера)
Кнопка «Импорт фото по ссылкам» принимает `images.csv` вида `slug;url1;url2;...`.
Скачивает изображения **сервер** (браузер этого не умеет), конвертирует в WebP,
пропускает дубли по SHA-256 и привязывает к машинам. Большие пачки идут несколько минут — страницу не закрывать.

## Массовая загрузка фотографий из папки-медиатеки (сервер)
1. Сложите фото в медиатеку на сервере: `/var/lib/inavto/media-in/<slug>/*.jpg` (папка на машину) или плоскими файлами `<slug>-1.jpg`, `<slug>-2.jpg`. Файл со словом `main` в имени станет главным.
2. Запустите: `bash /opt/inavto/deploy/update-images.sh --all`
   Другие режимы: `--brand "BYD"`, `--slug zeekr-7x`, `--missing-images`, `--update-only`, `--dry-run`.
3. Скрипт сам: конвертирует в WebP 1600px/85%, удалит EXIF, разложит в `uploads/cars/<slug>/` (main + галерея до 20 шт.), пропустит дубли по SHA-256, обновит `photos` и `updated_at` в базе, покажет прогресс и итоговую статистику. Журналы: `/var/lib/inavto/logs/{import,errors,not_found}.log`. Повторные запуски безопасны, после обрыва продолжает с места остановки (checkpoint).
Источники только разрешённые: собственная медиатека или лицензированный список URL (`IMAGES_URL_CSV`). Парсинг чужих сайтов не поддерживается сознательно.
- Изменения видны на сайте сразу (без пересборки).

## Переменные окружения
На сервере лежат в `/etc/inavto.env` (создаёт `deploy/install.sh`):
- `ADMIN_TOKEN` — ключ входа в админку. Длинная случайная строка, например `openssl rand -hex 24`.
- `BOT_TOKEN`, `ADMIN_CHAT_ID` — телеграм-бот для заявок (как раньше).
- `DB_PATH` — путь к базе; на VPS — `/var/lib/inavto/inavto.db` (данные переживают обновления кода).
- `UPLOAD_DIR` — папка загруженных фото; на VPS — `/var/lib/inavto/uploads`.
- `PORT` — порт бэкенда (3000), nginx проксирует на него `/api`, `/uploads`, `/admin`.

## Подключение сайта
Если сайт и бэкенд на **одном домене** (наш вариант на VPS: nginx раздаёт статику и проксирует `/api`) — настраивать ничего не нужно: сайт сам берёт каталог с того же домена.

Если бэкенд на **другом** домене, на страницах сайта до `js/main.js` добавить:
```html
<script>window.INAVTO_API = 'https://<адрес-бэкенда>'</script>
```
В обоих случаях: если сервер недоступен, сайт молча показывает встроенные 16 моделей (data.js).

## Безопасность
- Все изменяющие запросы API (каталог, заказы, список заявок) требуют `Authorization: Bearer ADMIN_TOKEN`.
- Публично доступно только чтение каталога.
