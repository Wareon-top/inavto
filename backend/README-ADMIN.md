# Админка каталога INAVTO ASIA

Адрес после установки на сервер: `http://<IP-сервера>/admin` (с доменом — `https://домен/admin`). Страница закрыта ключом.

**Установка на VPS (Sprintbox)** — пошагово для владельца: `docs/DEPLOY-SPRINTBOX.md`. Скрипты: `deploy/install.sh` (первичная установка) и `deploy/update.sh` (обновление).

## Что умеет
- Добавлять/редактировать/скрывать/удалять автомобили каталога сайта.
- Описание, характеристики, теги-фильтры, порядок вывода.
- Цены в трёх валютах: ₽ (под ключ, в млн — показывается на карточках), ¥ (цена в Китае), $ (опционально) — обе показываются на странице модели.
- Фото: перетащите файлы — они сжимаются в браузере до 1280px WebP и загружаются на сервер. Первое фото — главное (показывается на карточке вместо силуэта).
- Кнопка «Импортировать 16 моделей сайта» — первичное наполнение из встроенного каталога.
- **Импорт из CSV**: кнопка «Шаблон CSV» отдаёт таблицу-образец (открывается в Excel), заполняете и загружаете через «Импорт из CSV». Понимает UTF-8 и кодировку русского Excel, разделители `;` и `,`. Машины с совпадающим слагом обновляются — удобно массово менять цены. Колонка `cond` — new/used, `mileage` — пробег в км.

## CRM — заявки клиентов (вкладка «CRM · Заявки»)
Все заявки с сайта (квиз, визитка, формы моделей, калькулятор, PDF-гайд) попадают сюда — в дополнение к уведомлениям в Telegram.
- **Сводка-воронка**: Новая → В работе → Расчёт отправлен → Договор → Выкуп и доставка → Выдано / Отказ. Клик по плашке — фильтр.
- **Красный счётчик** на вкладке — сколько новых заявок ещё не разобрано.
- **Статус** меняется прямо в строке и сохраняется сразу; **комментарий менеджера** — свободное поле рядом (сохраняется, когда убрали курсор из поля).
- **Телефон кликабелен**: звонок в одно касание, рядом ссылка WhatsApp.
- **Поиск** по имени/телефону/модели и **выгрузка в CSV** (открывается в Excel) — для отчётов.
- Видно всё, что клиент выбрал на сайте: бюджет, срок покупки, способ связи, интересующая модель.
Удаление заявки — безвозвратное (для спама и тестов); рабочие заявки закрывайте статусом «Отказ», чтобы сохранялась история.

## Журнал сделок (вкладка «Журнал сделок»)
Рабочий журнал: каждая строка — один автомобиль клиента. В таблице: Статус · Клиент · Автомобиль · VIN · Китай · Россия. Клик по строке открывает карточку:
- **Информация**: марка и модель, комплектация, VIN, цвет, год, цена в Китае.
- **Клиент**: ФИО, телефон, Telegram, комментарий.
- **Статус-воронка**: 🔍 Поиск → ✅ Выкуплен → 📄 Экспорт оформлен → 🚛 В пути → 🛃 Таможенный пост → 📋 Лаборатория → 📑 ЭПТС → 🚗 Выдан клиенту. Смена — кликом по плашке.
- **Логистика**: город отправки, дата отправки, таможенный пост, перевозчик, номер контейнера/автовоза, ожидаемое прибытие, город выдачи.
- **Фото** (сжимаются в браузере и хранятся на сервере) и **журнал событий** — каждая смена статуса и комментарий с датой и автором (Офис / Представитель).

**Доступ китайского представителя.** В `/etc/inavto.env` добавьте вторую строку-ключ и перезапустите бэкенд:
```
echo "STAFF_TOKEN=$(openssl rand -hex 24)" >> /etc/inavto.env && systemctl restart inavto
```
Представитель заходит на тот же `/admin`, но со своим ключом (STAFF_TOKEN): видит **только журнал сделок** — без каталога, CRM-заявок и контактов клиентов (только имя). Может: менять статус, писать комментарии, загружать фото. Интерфейс переключается на 中文 кнопкой в шапке. Видео пока передаёт ссылкой в комментарии (файлы видео тяжёлые для VPS) или в Telegram.

## Документы (вкладка «Документы»)
Файловое хранилище компании прямо в админке:
- **Папки**: создать («+ Новая папка»), переименовать, удалить (вместе с файлами, с подтверждением). Плашки-папки со счётчиком файлов; «Без папки» — корень.
- **Загрузка**: перетащите файлы в поле или нажмите на него. Форматы: PDF, JPG/PNG/WebP, DOC(X), XLS(X), TXT, CSV, ZIP; до 15 МБ на файл. Скачивание — кнопкой, с исходным именем файла.
- **Документы автомобиля** прикрепляются в карточке сделки («Журнал сделок», секция «Документы») — их видит и китайский представитель, он же может загружать свои (инвойс, экспортная декларация). Каждая загрузка отмечается в журнале событий сделки («📎 Документ: …»). Удалять файлы может только админ.
Файлы хранятся в `/var/lib/inavto/uploads/docs/` — переживают обновления кода и попадают в общий бэкап данных.

## Массовая загрузка фотографий по ссылкам (из админки — без сервера)
Кнопка «Импорт фото по ссылкам» принимает `images.csv` вида `slug;url1;url2;...`.
Скачивает изображения **сервер** (браузер этого не умеет), конвертирует в WebP,
пропускает дубли по SHA-256 и привязывает к машинам. Большие пачки идут несколько минут — страницу не закрывать.

## Массовая загрузка фотографий из папки-медиатеки (сервер)
1. Сложите фото в медиатеку на сервере: `/var/lib/inavto/media-in/<slug>/*.jpg` (папка на машину) или плоскими файлами `<slug>-1.jpg`, `<slug>-2.jpg`. Файл со словом `main` в имени станет главным.
2. Запустите: `bash /opt/inavto/deploy/update-images.sh --all`
   Другие режимы: `--brand "BYD"`, `--slug zeekr-7x`, `--missing-images`, `--update-only`, `--dry-run`.
3. Скрипт сам: конвертирует в WebP 1600px/85%, удалит EXIF, разложит в `uploads/cars/<slug>/` (main + галерея до 20 шт.), пропустит дубли по SHA-256, обновит `photos` и `updated_at` в базе, покажет прогресс и итоговую статистику. Журналы: `/var/lib/inavto/logs/{import,errors,not_found}.log`. Повторные запуски безопасны, после обрыва продолжает с места остановки (checkpoint).
Источники только разрешённые: собственная медиатека или лицензированный список URL (`IMAGES_URL_CSV`). Парсинг чужих сайтов не поддерживается сознательно.
- Изменения видны на сайте сразу (без пересборки).

## Переменные окружения
На сервере лежат в `/etc/inavto.env` (создаёт `deploy/install.sh`):
- `ADMIN_TOKEN` — ключ входа в админку. Длинная случайная строка, например `openssl rand -hex 24`.
- `BOT_TOKEN`, `ADMIN_CHAT_ID` — телеграм-бот для заявок (как раньше).
- `DB_PATH` — путь к базе; на VPS — `/var/lib/inavto/inavto.db` (данные переживают обновления кода).
- `UPLOAD_DIR` — папка загруженных фото; на VPS — `/var/lib/inavto/uploads`.
- `PORT` — порт бэкенда (3000), nginx проксирует на него `/api`, `/uploads`, `/admin`.

## Подключение сайта
Если сайт и бэкенд на **одном домене** (наш вариант на VPS: nginx раздаёт статику и проксирует `/api`) — настраивать ничего не нужно: сайт сам берёт каталог с того же домена.

Если бэкенд на **другом** домене, на страницах сайта до `js/main.js` добавить:
```html
<script>window.INAVTO_API = 'https://<адрес-бэкенда>'</script>
```
В обоих случаях: если сервер недоступен, сайт молча показывает встроенные 16 моделей (data.js).

## Безопасность
- Все изменяющие запросы API (каталог, заказы, список заявок) требуют `Authorization: Bearer ADMIN_TOKEN`.
- Публично доступно только чтение каталога.

## Личный кабинет клиента (lk.<домен>)

Скрытый раздел для клиентов: страница со статусом их автомобиля по секретной
ссылке, без логинов и паролей. На основном сайте кабинет нигде не упоминается,
поисковикам вход запрещён (noindex + robots).

Как пользоваться:
1. Откройте сделку в «Журнале сделок» → блок «Личный кабинет клиента» →
   «Скопировать ссылку для клиента». Ссылка создаётся один раз и не меняется.
2. Отправьте ссылку клиенту в мессенджер. Он увидит: этапы заказа, фото,
   документы с пометкой «виден клиенту», ленту событий и контакты менеджера.
3. Сообщение клиенту в кабинет — поле «Сообщение клиенту в кабинет» в сделке.
   Обычные комментарии журнала остаются внутренними.
4. Документы, которые прикрепляете вы, сразу видны клиенту в кабинете.
   Загрузки китайского представителя по умолчанию скрыты. Управлять можно
   кнопкой «👁 виден клиенту / 🚫 скрыт от клиента» на конкретном файле.

Клиент НЕ видит: телефон/Telegram и заметки о себе, закупочную цену в юанях,
перевозчика/контейнер/таможенный пост, внутренние комментарии (в т.ч.
комментарии к смене статуса) и данные других клиентов.

Подключение поддомена (один раз):
1. В DNS-панели (Sprinthost) создайте A-запись с именем `lk` на IP сервера.
2. На сервере: `bash /opt/inavto/deploy/enable-lk.sh inavtoasia.ru ваш@email`
   — скрипт настроит nginx и выпустит HTTPS-сертификат.
